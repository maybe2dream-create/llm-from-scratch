# Query, Key, Value — 가중치 이전 단계

self-attention의 세 역할을 문장 하나로 따라가 본다. 학습 가능한 가중치 행렬(W_Q, W_K, W_V)이 들어오기 **전** 단계다 (책 §3.3).

## "가중치"는 두 가지 뜻이다

이 문서에서 말하는 "가중치 없이"는 **attention weight가 없다는 뜻이 아니다.** 둘을 구분해야 한다.

| 용어 | 무엇인가 | 이 단계에 있는가 |
|---|---|---|
| **attention weight** | softmax가 만드는 토큰 사이의 관련도 점수 (합이 1인 확률값) | **있다** — attention의 핵심이라 없을 수 없다 |
| **weight matrix** (W_Q, W_K, W_V) | 임베딩을 Q/K/V 공간으로 투영하는 학습 파라미터 | 없다 — 다음 단계(§3.4)에서 도입 |

## 예문과 토큰 임베딩

예문: `"The cat sat on the mat."` — 6개 토큰. 설명용 토이 임베딩(3차원)을 직접 지정한다. 실제로는 학습으로 정해지는 값이다 ([embedding-layer.md](embedding-layer.md) 참고).

| 토큰 | 임베딩 |
|---|---|
| The | `[0.10, 0.20, 0.00]` |
| cat | `[0.90, 0.10, 0.00]` |
| sat | `[0.00, 0.80, 0.30]` |
| on | `[0.10, 0.10, 0.10]` |
| mat | `[0.80, 0.20, 0.10]` |
| the (2번째 등장) | `[0.10, 0.20, 0.00]` — The와 **완전히 동일** |

## 세 역할

가중치 행렬이 없으면 세 벡터를 따로 만들 수 없다. 그래서 이 단계에서는 **토큰 하나의 임베딩이 세 역할을 동시에 겸한다. 숫자는 똑같고, 역할만 다르다.**

| 역할 | 산출 | 의미 |
|---|---|---|
| **Query** | 지금 문맥을 만드는 중인 토큰의 임베딩 그대로 | "나와 관련있는 게 누구지?" — 질문하는 주체 |
| **Key** | 문장 안 모든 토큰의 임베딩 그대로 (자기 자신 포함) | "나는 이런 내용이야, 비교해봐" — 비교당하는 대상 |
| **Value** | 문장 안 모든 토큰의 임베딩 그대로 (Key와 숫자 동일) | "관련있다면 이 내용을 가져가" — 실제로 섞이는 내용물 |

Key와 Value는 이 단계에서 **숫자가 정확히 같다.** 그럼에도 이름을 나누는 이유는 쓰이는 목적이 다르기 때문이다 — 하나는 "비교 기준", 하나는 "가져갈 내용". 가중치 행렬이 들어오면 숫자 자체가 갈라진다.

## 계산 — Query = "cat"

```
Step 1  Query = embedding("cat") = [0.90, 0.10, 0.00]
Step 2  Key   = 문장의 모든 토큰 임베딩 (위 표 그대로)
Step 3  score = Query · Key  (단순 내적, 코사인 아님)

        score(cat, The) = 0.11
        score(cat, cat) = 0.82
        score(cat, sat) = 0.08
        score(cat, on)  = 0.10
        score(cat, the) = 0.11   <- The와 동일
        score(cat, mat) = 0.74

Step 4  softmax → 0.127, 0.258, 0.123, 0.126, 0.127, 0.239   (합 = 1.000)
Step 5  context(cat) = Σ (weight_i × Value_i) = [0.4613, 0.2356, 0.0734]
```

`cat`의 원래 임베딩 `[0.90, 0.10, 0.00]`이 문맥을 반영한 `[0.4613, 0.2356, 0.0734]`로 바뀌었다. 자기 자신(0.258)과 `mat`(0.239)의 영향이 가장 컸다.

**`mat`이 두 번째로 큰 건 우연이 아니다.** `cat`과 `mat` 둘 다 첫 성분이 크기 때문이다. attention은 결국 "Query와 방향이 비슷한 Key에 큰 가중치를 준다"는 기하학 하나다 (내적 = 방향 유사성 × 크기).

## Query가 바뀌면 분포가 바뀐다

같은 문장, 같은 Key/Value인데 Query만 바꾼 결과:

| Query | The | cat | sat | on | the | mat |
|---|---|---|---|---|---|---|
| cat | 0.127 | **0.258** | 0.123 | 0.126 | 0.127 | 0.239 |
| sat | 0.150 | 0.138 | **0.265** | 0.143 | 0.150 | 0.154 |
| mat | 0.130 | 0.242 | 0.139 | 0.129 | 0.130 | 0.230 |

**"누가 묻는가"에 따라 답이 매번 달라진다** — attention이 "동적"이라는 말의 실제 의미다.

## 아직 위치 정보가 없다

Query=`cat`일 때 앞쪽 `The`(position 0)와 뒤쪽 `the`(position 4)가 **정확히 같은 점수(0.11), 같은 weight(0.127)** 를 받았다. 토큰이 같으면 임베딩이 같고, 임베딩이 같으면 결과도 같다. 이 공백을 위치 임베딩이 메운다 ([positional-embedding.md](positional-embedding.md), 2.8절).

## 다음 단계에서 바뀌는 것

가중치 행렬 W_Q, W_K, W_V가 들어오면:

1. **Q, K, V가 더이상 같은 숫자가 아니다** — 같은 임베딩이 각각 다른 행렬로 투영된다.
2. **유사도가 학습된다** — 지금은 "cat과 mat이 비슷하다"를 사람이 설계해 넣었지만, 실제로는 행렬이 학습으로 알아낸다.
3. **점수가 스케일링된다** — 내적 뒤 `1/√d_k`를 곱해 softmax가 극단으로 치우치지 않게 막는다.

> **가중치 행렬이 없어도 Query·Key·Value는 이미 서로 다른 역할이다 — 숫자가 같은 건 우연이고, 역할이 다른 건 필연이다.**
